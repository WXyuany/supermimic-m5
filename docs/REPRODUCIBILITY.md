# 实验记录与复现边界

## 测试设备与依赖

2026-10-23 在 Apple M5 MacBook、24 GB 统一内存、macOS 27.0、原生 arm64 Python 3.12.15 上完成训练。PyTorch 2.14.1 的 MPS 后端执行世界模型与策略学习；MuJoCo 3.16.0 / MuJoCo Warp 3.16.0 / Warp 1.18.0 在 CPU 执行物理仿真。**这不是 Metal GPU 物理仿真。** 依赖完整版本及哈希在 `uv.lock`。

首次安装需要 Apple Command Line Tools，以及能连接 PyPI、GitHub、Hugging Face 的网络。建议至少 15 GB 可用空间，完整训练建议 24 GB 或更多内存。视频渲染使用 GLFW，需要登录 macOS 桌面会话。其他 Apple Silicon 芯片/系统版本未逐一测试；不能承诺完全相同分数或运行时间。

## 真实训练过程

模型只在这台 Mac 上从随机初始化开始学习，没有使用 Linux/NVIDIA 服务器权重。

| 阶段 | 环境数 | 世界模型/策略 batch | 均匀/困难/记忆采样 | 温度 | 迭代范围 |
|---|---:|---:|---|---:|---|
| 基线 | 128 | 128 / 128 | 0.50 / 0.40 / 0.10 | 25 | 0 → 12500 |
| 调整后续训 | 1024 | 512 / 512 | 0.80 / 0.15 / 0.05 | 5 | 12500 → 21200 |

初始学习率 2e-4、seed 0、想象 horizon 32、原学习率日程 320000 次不变。阶段切换保留模型、优化器和分桶回报估计，只按新温度重建采样记忆。恢复时先采集 40 步新数据，因为检查点不包含 replay buffer。

公开模型选择 **21000 次 / 8368 次更新**，视频和全部 40 条评测与其一致。用户于 21200 次主动结束训练，额外 200 次模型保留在原实验目录，不冒充已评测的公开模型。训练曲线保留所有已记录标量：基线到 12900 次、续训到 21250 次；最后少量未保存迭代已舍弃，阶段续训从保存点 12500 开始，最后保留模型为 21200。约 5.2 小时有效训练（第一阶段约 1.7 h，第二阶段到 21000 约 3.5 h），不包含数据准备、排障、评测和视频生成。具体累计时间见原始标量 `time/hours`，每阶段重新计时。

`train.sh` 从零重复上述两阶段，到 **21000** 停止，随后评测与渲染。新增 `stop_at_iteration` 只决定停止点，不改变 320000 次学习率日程。为减少磁盘占用，公开脚本每 500 次保存；原第二阶段每 100 次保存。再次运行同一脚本会从各阶段最近保存点恢复。中断会损失最近保存点之后的进度，恢复会重新初始化仿真和 replay，因此不保证逐位相同。`Ctrl+C` 停止，不会自动后台重启。

## 评测含义

全部 40 条训练动作从首帧开始、确定性策略、关闭动作/观测/重置噪声和域随机化，按上游规则在失稳时提前结束。每条归一化回报为 `sum(reward) / (0.1 * executed_steps)`，然后取 40 条的算术平均。提前失败后的未执行帧**不会补零**，因此必须结合失败数、执行步数一起看。step-weighted 是按实际执行步数加权的指标。

这是训练动作集上的跟踪评测，不是留出集泛化结果，也不是多随机种子平均。所用 anchor-relative 观测额外提供 9 维相对位姿，和原论文纯本体观测不是同一口径。没有宣称达到原论文分数。

展示的 walk/dance/jumps 视频各 20 秒，左侧是真实策略控制的物理仿真，右侧是参考轨迹。两侧镜头各自跟随根部，视觉居中不代表世界坐标位置误差为零。短预览不是完整动作成功率；例如 dance1_subject1 在完整评测中较晚失败，原始 JSON 如实保留。

## macOS 适配

- 物理环境留在 CPU，策略动作和采样 replay 在 CPU/MPS 间显式传输。
- MPS 编译时限制单次融合的 I/O buffer 数为 16，避开 Metal 的绑定数量限制。
- 使用设备对应的同步；可微 FK 的关节限制与初始状态放在学习设备上。
- 原子保存检查点；恢复后先填充 40 步 replay。
- 可配置回报采样比例、温度，并记录 top-10 概率集中程度。

原实验 CPU/MPS 数值对照：FK 最大绝对误差约 1.9e-6；实际 replay 上编译 MPS 与 CPU 的世界模型梯度相对 L2 误差约 3.04e-6，策略约 2.26e-5。此项支持所测算子的数值一致性，不等同于端到端训练完全确定性。原始诊断见 `results/metal_training_parity.json`。

## 常见问题

- `MPS unavailable`：确保使用原生 Apple Silicon 终端而非 Rosetta。不要用 CPU fallback 掩盖错误。
- 首次长时间没显示训练迭代：首次 `torch.compile` / Warp 编译需要时间，查看 `logs/*.console.log`。
- 网络超时：终端不会自动继承所有图形代理软件设置。按自己代理的 HTTP 端口设置 `HTTPS_PROXY` 和 `HTTP_PROXY` 后重试；脚本会校验已下载文件并续用。不要照抄别人的代理地址。
- 下载中断或数据损坏：重跑 `setup.sh`；CSV 校验 SHA256，损坏 NPZ 会重新转换。
- 内存不足：关闭占内存程序；降低环境数和 batch 是另一种实验配置，分数与时长需要重新测量。
- 查看 TensorBoard：`bash scripts/macos/tensorboard.sh`，浏览器打开 http://127.0.0.1:6006 。
- 想从头重训：把已有 `logs/m5_stage1`、`logs/m5_stage2` 移到其他位置，再运行训练脚本；不要覆盖唯一的实验成果。
